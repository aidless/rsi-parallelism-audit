## (a) RecursiveMAS 77.8%/1360s 与 ConvRSI 复现 71.4%/2658s 的冲突

**结论**：两组数字不冲突，是**跨 benchmark + 跨硬件 + 跨协议混读**。77.8%/1360s = RecursiveMAS 自家 Table 2 的 MATH500（Light, r=3, H100/A100, 5 runs）读数；71.4%/2658s = ConvRSI 用其 released checkpoints 在 MATH-500（GSM8K 类数学集，RTX 4090D，4 seeds，2,000-token 上限）上的 Table 2 读数。**不是**模型不同、**不是** r 定义不同（两文 Sequential-Light 三模型逐字相同，r 同为 recursion round r∈{1,2,3}）；硬件与数据集不同是确定差异，但各自贡献多少**无法定量判定**（缺同 benchmark 同硬件的交叉重跑）。

**逐字证据（数字出处）**
- abs 号-题：https://arxiv.org/abs/2604.25917 → "Recursive Multi-Agent Systems"；https://arxiv.org/abs/2611.20891 → "From Recursion to Convolution: Parallel Self-Improvement for Multi-Agent Systems"。
- RecursiveMAS §5 "Tasks and Datasets" 原文列 9 基准：MATH500、AIME2025、AIME2026、GPQA-Diamond、MedQA、LiveCodeBench-v6、MBPP Plus、HotpotQA、Bamboogle；**全文无 GSM8K**（本地 /tmp/rm.txt 中 "gsm" 仅命中参考文献 "Gsm-symbolic"）。来源：https://arxiv.org/html/2604.25917v2
- RecursiveMAS Table 2 "Main results ... over Different Recursion Rounds"，RecursiveMAS r=3 行 / Math500 列：Acc. **77.8**、Time **1360** s、Token **519**；同表 r=1 75.8/825、r=2 76.6/1096。来源同上（表格按 Math500/AIME2025/... 列展开）。
- RecursiveMAS §5："we freeze all LLM agent parameters and update only the inner/outer RecursiveLink"、"report the mean performance over five independent runs"；§5.1 前："The average standard deviation of RecursiveMAS across 5 runs is ..."；附录："All experiments are conducted on H100 and A100 GPUs."
- ConvRSI §5.1 "Datasets and metrics"："We evaluate mathematical reasoning on MATH-500 [Lightman et al., 2024; HuggingFaceH4, 2024] ... report both metrics as percentages averaged over four random seeds"；同节 "Baselines and backbones"："Both use Qwen3-1.7B as the planner, Llama-3.2-1B-Instruct as the critic, and Qwen2.5-Math-1.5B-Instruct as the solver"（与 RecursiveMAS Table 1 的 Sequential-Light 三模型逐字一致）。
- ConvRSI §5.1 "Inference and evaluation"："For MATH-500, we set ... the maximum generation length to 2,000 tokens ... We measure inference efficiency on NVIDIA RTX 4090D GPUs"；Table 2 注："All results are reproduced using NVIDIA RTX 4090D GPUs"。

**来源 URL**：上述 abs 两页 + 两篇 HTML 全文（§5/Table 2/附录）。
**证据等级**：A（每个数字的节/表位置与口径逐字可核）；冲突归因中的「硬件+benchmark 混读」= B（多段原文组合判定）。
**未核**：两篇测试集具体题数（ConvRSI 的 2,000-token 上限已核）；token 统计口径是否完全一致；是否存在同 benchmark 同硬件的 RecursiveMAS 复跑（文中未见）。**判定：禁止把 77.8% 与 71.4% 直接相减比较。**

## (b) MILO：orchestrator 规则自身是否为可编辑对象

**结论**：**否**。摘要的 "strategy" 指搜索配置 S（memory、island–mutator assignment、curriculum）及 LLM 在固定四类动作中的选择，**不等于** orchestrator 的诊断/干预规则本身；后者的动作集、诊断→动作映射、mutator 池、调用上限均为固定设计。T4.md 中「orchestrator 是否可编辑：未核」可由正文闭合。

**逐字证据**
- abs 号-题：https://arxiv.org/abs/2609.38349 → "MILO: Automated Harness Discovery via Orchestrated Multi-Agent Evolution"（2026-09-29）。
- 摘要（§Abstract）："co-evolves the harness and its own search strategy ... an orchestrator agent that adapts the search by grafting and speciating lineages, reassigning mutators, and revising the curriculum."
- §4.1.3："Let the search configuration entering round r be S_r: the memory, the island-mutator assignment, and the curriculum of evaluation tasks."
- §4.1.3 Diagnose/Intervene："identifies the bottleneck ... as one of four sources: the mutator ...; the lineage ...; selection ...; or the population ..."、"The four actions correspond to the four diagnoses"、"The loop then applies mechanically, except Graft, whose child must clear admission"、"Overall, by rewriting S, the search self-adapts its memory, mutators, and curriculum."
- §4.1.2："The pool M is identical in every run and holds six coding agents"；附录 A.1："The orchestrator is itself a Claude Code agent (with Opus 4.8) that applies at most two moves per intervention."
- Table 1（MILO 行）："strategy / Harnesses / inter-island graft & speciation / Dom, Sim self-adapt based on memory state / Multi-Agent Reassign mutators across islands"；附录 C "Prompts Used by MILO" 是固定 prompt 列表。
- 来源：https://arxiv.org/html/2609.38349v1（§4.1.2、§4.1.3、Table 1、附录 A.1/C）。

**来源 URL**：https://arxiv.org/abs/2609.38349 ；https://arxiv.org/html/2609.38349v1
**证据等级**：A。
**未核**：未逐行审计随代码发布的 orchestrator 实现（如 GitHub repo）；仅就论文正文可判定。摘要级"两层"成立，规则级自编辑不成立；MILO 仍不越过 Inventa/Hyperagents 的严格 RSI 分界线。

## (c) AutoDNA：co-evolution 是否改写模型权重

**结论（已用完整 arXiv 正文闭合到正文级）**：arXiv 16 页正文把 "co-evolution" 落实为**实验程序/协议、假设、知识库条目、控制代码与仪器原子服务的迭代改进**，逐字可见的反馈闭环是 HEVA 回传结果 → EPA/HPA/LRA 重写 procedure；**正文未描述任何模型权重被实验数据改写**（无 fine-tune/retrain/update weights 的机制或字句）。所以就 arXiv 可判定范围：**没有证据支持"权重改写"，不是 RSI 意义上的模型自改**；"只改 prompt"也不准确——改的是实验程序/协议/代码与知识库。Nature 正刊 Methods/SI 付费墙部分仍标未核。

**逐字证据（数字与出处）**
- abs 号-题（HTTP 200）：https://arxiv.org/abs/2507.02379 → "An AI-native experimental laboratory for autonomous biomolecular engineering"（2025-07-03；题名中无 "AutoDNA"，为系统名）。
- 摘要（PDF p.2）："Founded on a co-design philosophy of models, experiments, and instruments, the platform supports the co-evolution of AI models and the automation system."；"autonomously manages instrumentation, formulates experiment-specific procedures and optimization heuristics"。
- §"AutoDNA system architecture"（PDF p.3）："These agents leverage LLMs' language understanding and reasoning capabilities to enable inter-module collaboration and co-evolution."；同段："Agents continuously monitors real-time experimental feedback and instrument status, enabling autonomous procedure optimization"。→ "co-evolution"的句法主语是 agents（模块间），不是权重。
- §架构（PDF p.3–4）：六个 agent 分工 EPA/HPA/LRA/RMA/PDA/HEVA；"After execution, HEVA reports the validated results back to EPA, which determines if further optimization is needed. If needed, EPA leverages the Hypothesis Proposer Agent (HPA) to identify improvement pathways, iteratively generating refined procedures until meeting preset objectives."（明确的被改对象 = procedure）。
- §架构（PDF p.4）："Program Developer Agent (PDA) transforms instrument functionalities—extracted from technical documentations—into AI-native abstractions called 'atomic services' ... Each atomic service is represented as a Python object containing natural language descriptions"；"HPA analyzes data to generate improvement hypotheses ... EPA then integrates these hypotheses with LRA's literature insights to formulate revised procedures."（协议/文献/代码层，无权重层）。
- §应用（PDF p.11）："the enzymatic de novo synthesis procedure had been generated in previous experiments, we archived it in the system's knowledge base, allowing agents to retrieve and execute it directly"（持久化的是 procedure 条目，不是模型 checkpoint）。§Discussion（p.12–13）："leveraging the reasoning capabilities of LLMs to extract knowledge from literature and formulate experimental hypotheses ... enabling a closed-loop 'design-experiment-optimize' cycle"。
- 全文检索：pymupdf 提取的 16 页正文中 `fine-tun`=0、`training`=1（仅参考文献题名）、`updat`=0、`weights`=0；无"模型权重被数据改写"的段落。（反证只是"正文未写"，不排除未披露实现。）
- 数字（本条不作机制依据）：p.3 "over 20 instruments across more than 9,300 hardware steps"、"3 folds" 吞吐；p.11 read-write 演示 "25 instruments across 9,365 hardware steps"、"162.9 hours"。
- Nature 新闻 DOI 10.1038/d41586-026-03552-8 = Ledford 写的 **News & Views**（Crossref: type journal-article, reference-count=1, pages 283-284, volume 659），它引用的研究正刊 = Wu, M. et al. **10.1038/s41586-026-11228-6** "An AI-native experimental laboratory for autonomous biomolecular operations"（Nature 659, 2026-11-04；Crossref reference-count=53；EuropePMC 已收录）。此前一直对着 News 的 DOI 找 Methods，找错对象。Nature 正刊摘要（web_fetch 已取）逐字："Through the co-design of models, experiments and instruments, AutoDNA realizes the **co-evolution of AI and the automation system** within an end-to-end multi-user framework."；"autonomously orchestrates over 20 types of instruments across more than 11,000 steps"。摘要与 arXiv 机制一致（co-design/co-evolution = models+experiments+instruments 协同），无权重改写表述。**Methods/SI 正文仍在付费墙后（preview of subscription content）未核**；但换对 DOI 后确认此前的"未核"里有一半是找错了对象，Nature 摘要本身并不构成新悬念。

## (e) IdeaBench 原题名/编号与 DN7/DN8 定义核对

**结论**：原论文 = **"IdeaBench: Benchmarking Large Language Models for Research Idea Generation"**, arXiv:**2411.02429**（2024-10-31；Sikun Guo, Amir Hassan Shariatmadari, Guangzhi Xiong, Albert Huang, Eric Xie, Stefan Bekiranov, Aidong Zhang），KDD 2025（DOI 10.1145/3711896.3737419，来自 dblp/ACM 检索片段，未二次验 DOI 页）。**原论文没有 DN7/DN8 定义**：这两个指标是 Inventa 新增的自家 novelty judge 口径，**不能称为 IdeaBench 原始指标**。数据集转述（2,374 / 23,460）与原论文一致；但 Inventa 的出处标注应为附录 **A.2 / A.4**，不是 B.3（B.3 是结果讨论）。

**逐字证据**
- abs 号-题（HTTP 200）：https://arxiv.org/abs/2411.02429 标题逐字如上。
- 摘要："a two-stage process: first, using GPT-4o to rank ideas based on user-specified quality indicators such as novelty and feasibility, enabling scalable personalization; and second, calculating relative ranking based 'Insight Score' to quantify the chosen quality indicator."
- §数据集（原文）："We curated 2,374 target papers and their corresponding 29,408 reference papers. The total number of filtered reference papers is 23,460."；过滤规则："We exclude reference papers with fewer than five citations"、"We also exclude reference papers that are not cited in the background section of the target paper"。
- §评价框架："We define ... to represent the 'Insight Score' for a given LLM based on a specific quality indicator ..."；公式为 MathML，HTML 纯文本提取丢失。原论文全文 `DN7`/`DN8` 出现次数 **0**，`distinct ... rated` 口径 **0**。
- Inventa 附录 **A.4 Evaluation Metrics**（/tmp/inv.txt:1345）："We add measures from our own novelty judge, a frontier LLM calibrated on RINoBench (Appendix ) that rates every generated idea from 1 to 10: the number of distinct ideas per paper rated at least 7 (our primary measure) or at least 8, merging near-duplicates among them (Cohere Embed v4, cosine 0.8)"。→ DN7 = 每篇被该 judge 评 ≥7 的去重 idea 数；DN8 = ≥8。
- Inventa 附录 **A.2 Benchmark Details**（/tmp/inv.txt:1198）："IdeaBench (Guo et al., 2025) pairs 2,374 influential biomedical papers published in 2024 with 23,460 references, research articles with at least five citations that each paper cites in its background section ... 904 training, 734 validation, 736 test papers." 与原文 2,374/23,460 一致（原论文另报接收时 29,408 篇，过滤后 23,460）。
- 来源：https://arxiv.org/html/2411.02429v1 ；https://arxiv.org/html/2611.21847v1

**来源 URL**：https://arxiv.org/abs/2411.02429 ；https://arxiv.org/html/2411.02429v1 ；https://dl.acm.org/doi/10.1145/3711896.3737419
**证据等级**：A（abs 号-题、数据集数字、DN7/DN8 缺席与 Inventa 新增定义）；DOI = B（检索片段）。
**未核**：Insight Score 公式的逐字数学形式（MathML 未被纯文本提取）；KDD DOI 页未二次打开；原论文 "published in 2024" 这一年份表述是否为原文所写（Inventa 转述，原论文 §数据集未在已读段出现该年份）。
