# T1｜RSI 从递归到并行/卷积：ConvRSI 式"卷积替代递归"的技术实质

> 范围：只依据已实测抓取的 arXiv abs 页、项目页、GitHub README、论文 HTML 正文；数字逐处标源。HTML 归档被截断处一律写"未核"。证据采集时间：2026-11-19。
> 一句话结论：**ConvRSI 是"把递归的载体从文本 token 换成隐状态 + 同步图/卷积算子"，不是把递归消掉**。跨轮依赖 `M^(r)=G_A(C(Z_static,Q(M^(r−1))))` 仍在；真正并行的是**轮内**（slot/feature 并行、GCN 节点同步）与**轮间前缀可预先算好**。收益只在 Sequential-Light 的 MATH-500 一侧复算成立，MBPP+ 一侧的加速随 r 的增长几乎消失。

## 2. 机制解剖

### 2.1 四个部件分别做了什么

**(a) intra-agent 1-D conv（轮内、真并行）** `[H1 式(5)(6)]`
- 每个 agent i 的 5 类特征栈（task / role / system / experience / message，顺序固定）被投影到共享宽度 D；depthwise 1-D conv **沿 feature 轴**，每 channel 独立核，默认 kernel=5、dilation=1、same padding；逐 slot 施加，slot 轴保持 → K 个 slot 之间可并行。
- `V′ = LN[V + GELU(Conv(V))]`，后接 gated pooling（softmax β）→ 残差 MLP → 归一化投影 ψ_i → local message `u_{i,k}`。
- 静态槽 `H_{i,f}=sg[F_i(Emb_i(x_{i,f}))]` 用 stop-gradient，**每个样本只算一次、跨轮复用**——这是把"每轮重新编码静态文本"的成本砍掉的真正来源 `[H1 §静态编码]`。
- 并行性：轮内 feature/slot/channel 维可并行；**跨 r 仍串行**，因为 conv 的输入 message 槽来自上一轮（见 2.2）。

**(b) inter-agent GCN（轮内、真并行；轮间串行）** `[H1 式(7)、Table 1]`
- `M_k = LN[GELU(S U_k W_g + 1 b_g^T)]`，`S = D̃^{-1/2} Ã D̃^{-1/2}`，`Ã = A + I`；邻接 A 编码协作拓扑：Sequential 为 `A_{i+1,i}=1`（有向链），Mixture 为指定接收节点的加权星形，Distillation 非对称，Deliberation 互反。
- 图权重跨 agent、**跨轮共享**；正文原话 "The GCN updates those nodes synchronously" ——节点更新同步，这是相对 RecursiveMAS"逐 agent 链式传递"的结构性并行。
- 复杂度 `C_graph = O(BK[ND² + N²D])`，每轮一份；R 轮总计 `R(C_local + C_graph)` `[H1 式(14)(15)]`。N 大时 N²D 项会吃掉并行收益——这是可测的边界条件。

**(c) latent soft prefix（把递归从 token 空间搬到隐空间）** `[H1 式(9)(10)、R1]`
- `Q_i: R^D → R^{H_i}`；递归特征 `z_{i,msg,k}^{(r)} = Q_i(m_{i,k}^{(r−1)})`（r>1）；每轮 prefix `p_{i,k}^{(r)} = Q_i(m_{i,k}^{(r)})`。
- 核心递归 `M^(r) = G_A( C(Z_static, Q(M^(r−1))) )`，首轮 message 用 masked zero。正文："we can run the convolutional rounds in order before the scheduled LLM forwards and store the resulting K-token prefix p_i^{(r)} for each agent and round."
- 推论：**prefix 可以预计算并与实际 LLM 调度解耦**，但"in order"明确说明 r 个 conv–GCN 轮仍是顺序扫描。推理时中间 invocation 全在 latent space（InnerLink 把末隐状态映射成下一个连续输入，OuterLink 按 Π 路由），只有最终 Solver/Summarizer 解码文本 `[R1]`。
- README 超参：`--max-steps 3`（conv–GCN 与协作轮数）、`--csi-prefix-tokens 8`、`--d-model 512`、`--max-feature-tokens 1024`、`--max-prefix-tokens 80`、`--latent-length 32` `[R1]`。这些数决定"每轮便宜多少"，也是复现必须对齐的口径。

**(d) inner-outer 两段训练（成本被转移到这里）** `[H1 式(11)、R1]`
- Inner：每个 agent 用 masked message 跑一次本地算子，得到 soft prefix，冻结 LLM 在 teacher forcing 下预测参考 token；默认损失是变换后 detached hidden states 与 reference-token embeddings 的 cosine alignment（`--inner-ce-weight 1` 才加 local CE）；N 个 loss 独立、`--inner-parallel` 可并发 `[R1]`。更新 slot reader / local operator / prefix map；InnerLinks 只在此阶段更新。
- Outer：teacher-forced collaboration + 最终轮答案 token CE，**沿 R 轮展开**，联合更新 local modules、GCN、OuterLinks；backbone 与 InnerLinks 冻结 `[H1 式(11)]`。
- 所以"免解码"省下的是**推理时**的文本 decode/re-encode；训练时仍要为 R 轮递归保留计算图、做 BPTT 式信用分配。串行成本没有消失，而是从推理 token 移位到训练 unroll 与算子训练。

### 2.2 哪一步依赖 r，哪一步真并行

| 步骤 | 是否依赖轮数 r | 是否真并行 | 证据 |
|---|---|---|---|
| 静态特征编码 `sg[F_i(...)]` | 否（每例一次） | 是（各 agent/feature 独立） | `[H1 静态编码]` |
| intra-agent depthwise conv | 每轮执行一次 | **轮内** slot/feature/channel 并行；跨轮串行 | `[H1 式(5)]` |
| inter-agent GCN | 每轮执行一次，权重跨轮共享 | **轮内**节点同步；跨轮串行（`M^(r−1)` 输入） | `[H1 式(7)(10)]` |
| soft prefix 生成 | 每轮一份 `p_i^{(r)}` | 可在 LLM 调度前按序预计算 | `[H1 §Inference]` |
| LLM invocation / InnerLink rollout | 随 r 线性增长（每轮每 agent） | 调度 Π 仍顺序；latent-length=32 步 invocation | `[R1]` |
| 最终文本解码 | 只在末尾一次 | 不适用 | `[R1]` |
| Outer 训练展开 | 显式展开 R 轮 | 不可跨 r 并行（梯度沿递归链） | `[H1 式(11)]` |

### 2.3 "替代"还是"补充"？——判定：**补充（重构载体），不是消除递归**

1. **直接反证**：式(10) 含 `Q(M^(r−1))` 的显式数据依赖；`--max-steps 3` 仍在控制轮数；Table 2 显示 ConvRSI 精度随 r 上升（MATH-500 71.6→72.4→75.0；MBPP+ 30.0→30.3→32.9，r=1/2/3）`[H1 Table 2]`。若递归真被消掉，r 不应是有效旋钮。
2. **稳定性条件本身就是递归语言**：`κ = L_LN L_σ ||S||₂ ||W_g||₂ L_C L_Q`，κ<1 时扰动收缩、`max(κ,b)<1` 足以让扰动随轮消失 `[H1 式(12)(13)]`。这等价于承认系统是一个迭代动力系统，需要收敛条件。
3. **它替代的是"文本中介"**：相对 RecursiveMAS 的逐 agent latent thoughts _chain_ 与 Recursive-TextMAS 的文本消息，ConvRSI 用 depthwise conv 一次刷新 agent 内多特征、用 GCN 同步刷新多 agent，并把中间产物压成 K-token prefix，避免 decode→encode `[A1 摘要；H1；R1]`。因此更准确的说法是 **"把递归从昂贵的自回归文本环，迁移到廉价的隐状态同步环"**。
4. **可替代的边界**：若把 `M^(r)` 的迭代用一次前馈近似（截断 unroll），需 κ<1 且有误差上界；论文只给收缩判据，未核到"一步截断等价"的证明或实验——**未核**。

### 3.2 前提清单（少一条就可能复现不出）

1. **frozen LLM**：backbone 全程冻结，只训 slot reader / local conv / prefix map / GCN / OuterLinks `[H1 式(11)；H2 §训练]`。换成需要微调 LLM 的设定，训练成本账本完全不同。
2. **latent 传递免解码**：中间 invocation 不生成文本，只有最后一轮最后 agent 解码 `[R1；H1 §Inference]`。这是 `m|V|d_h` → `m d_h²` 复杂度替换的来源 `[H2 Proposition 3.1]`；若强制中间输出可读文本，收益消失。
3. **小模型异构团队**：Sequential-Light 三个 1B 级模型（见 3.1）；Mixture 用 DeepSeek-R1-Distill-Qwen-1.5B / Qwen2.5-Coder-3B / BioMistral-7B / Qwen3.5-2B `[R1；H2 Table 1]`。ConvRSI 的 `(C_local+C_graph)` 在 H_i 小、N 小时才远低于文本解码成本。
4. **固定超参**：`max-steps 3`、prefix tokens 8、d-model 512、max-feature-tokens 1024、max-prefix-tokens 80、latent-length 32 `[R1]`；K 与 D 直接进 `C_local/C_graph`。
5. **同口径计时**：总 benchmark 墙钟、RTX 4090D、四 seed 均值、`top-p 0.95`；ConvRSI 摘要/正文**未核到标准差**（RecursiveMAS 自家报 ±0.0041 acc / ±26s / ±33 tokens `[H2 Table 2]`）——无方差对照时，3.6pp 的稳健性未核。
6. **数据洁净度**：Sequential-Math 1,904 行中"原始 split 含 6 条与 MATH-500 归一化后完全相同的行" `[R1]`；即约 6/1904 ≈ 0.32% 的显式重叠（复算）。这是污染疑点，不是已证实作弊；复现必须先去重叠再报数。

### 3.3 "只是把串行成本转移给训练"的成立条件

- 若把 Outer 的 R 轮展开训练计入总成本，且每次换 benchmark/拓扑都要重训 local modules+GCN+OuterLinks，则训练侧 BPTT 长度 ∝ r、成本 ∝ 数据量 × R；论文只报推理墙钟，**训练 GPU 小时未核** → 此时"收益"是推理/训练之间的位移，不能称总成本下降。
- 若 N 增大使 `C_graph` 的 `N²D` 项上升，或 K/D 增大使 `C_local` 上升，或需要中间文本可解释，则并行算子的额外开销可能反超省下的 decode 成本。判据见 §4.3。
- 若 backbone 换成大模型（H_i 大、解码吞吐相对便宜），`m|V|d_h → m d_h²` 的相对优势缩小；本实验只在 1B–7B 级验证 `[R1；H2 Table 1]`，大模型外推**未核**。

## 4. 同族对照

### 4.1 与 RecursiveMAS / Recursive-TextMAS（同一条线的前后代）

- **RecursiveMAS** `[A2；P2；H2]`：把整个 MAS 当作 latent 空间里的一个递归计算；Inner Link `R_in(h)=h+W₂σ(W₁h)`、Outer Link `R_out(h)=W₃h+W₂σ(W₁h)` 负责同维/跨异构隐宽传递；最后一个 agent 的 latent thoughts 回传第一个 agent 闭环。训练同样冻结 LLM、只更新 RecursiveLink，inner cosine + outer CE 穿链反传。**差异**：RecursiveMAS 没有 conv/GCN；每 agent 内部是 m 步自回归 latent thoughts，跨 agent 按链逐个传递；ConvRSI 用一次 depthwise conv 刷多特征、用 GCN 同步刷多 agent，并把每轮产物缓存成 prefix。`[A2 摘要]` 报 9 benchmark 上平均 +8.3%、1.2–2.4× 加速、34.6–75.6% token 下降；`[H2 Table 2]` 自家 MATH-500 r=3 为 77.8%/1360s/519 tokens——与 ConvRSI Table 2 里被复跑的 RecursiveMAS 71.4%/2658s/556 **不是同一组读数**，禁止混比（口径冲突点）。
- **Recursive-TextMAS**：不是独立论文（**未核**），是 RecursiveMAS 论文内定义的"结构相同但用文本消息"的 baseline `[H2 §Baselines]`，ConvRSI Table 2/5 沿用。它的存在正是为了把"latent vs text"这一 factor 单独隔出来；在 ConvRSI 复跑口径下 MATH-500 r=1/2/3 为 71.4/71.0/69.6（精度随 r **下降**），时间 2254/3761/4721s `[H1 Table 2]`。

### 4.2 与另外三族（不同轴，别当成同一技术的变体）

| 项目 | 实际差异 | 出处 |
|---|---|---|
| ModularRSI | 进化的是 **harness 模块**（Agent Loop / Tool Use / Observation Management / Context Management / Task Completion Detection），用成功/失败轨迹对比 + 跨任务聚合；2,000 条 evolution tasks 与 benchmark不相交；测 TB2.0 / SWE-Bench Verified。**不优化递归轮、不用卷积** | `[A3 摘要]` |
| MASS | 单 base model 迭代 propose/execute/self-evaluate 多 agent workflow，workflow 进化 + 自生成轨迹 SFT 交替；两轮 Qwen3.6-27B 上每输出 token 性能高 1.2–1.6×。**关心训练自我监督，不关心轮内并行** | `[A4 摘要]` |
| Hermes+ | 来自 PAST-Bench（26 scenarios / 204 episodes，7 base models、4 frameworks）；在 Hermes 上做五个 stage 干预，最强在替换过期状态任务，效果 capability-/model-dependent。**测 retained experience，不是递归降延迟** | `[A5 摘要]` |
| ConvRSI Table 5 的对照 | ModularRSI(Qwen3.5-4B) 67.1/32.1、Hermes+(Sequential-Light solver) 64.6/28.6、Hermes+(Qwen3.5-4B) 67.2/27.3、MASS Level-0/1 62.8/23.5、68.7/28.7、Recursive-TextMAS r=3 69.6/29.1、ConvRSI r=3 75.0/32.9 `[H1 Table 5]`。**这些是换成 Qwen 系 solver 的适配版**，不是各项目原始论文数字；正文称 ConvRSI 对 TextMAS 领先 5.4pp/3.8pp（复算 75.0−69.6、32.9−29.1 一致） | `[H1 §5.4]` |

### 4.3 判据（可数、可测，回答"什么时候成立 / 什么时候只是转移成本"）

**判据 A：跨轮并行是真的吗？——检查计算图，不检查宣传语。**
- 可数条件：计算 `M^(r)` 对 `M^(r−1)` 的边是否存在。存在 → 递归未消除（ConvRSI：存在，`[H1 式(10)]`）。
- 可测条件：固定输入，逐轮注入扰动 δ 并测 `||δM^(r)||` 的衰减率，与 `κ = L_LN L_σ ||S||₂ ||W_g||₂ L_C L_Q < 1` 比较；κ≥1 时所谓"廉价多轮"不可用。

**判据 B：延迟收益是真的吗？——同 r、同 benchmark、同硬件、同 seed 口径下测两套量。**
- 可测条件 1：算 `g_method = T(3)/T(1)`。ConvRSI MATH-500 = 1459/1162 = 1.256，RecursiveMAS = 2658/1409 = 1.886（复算 `[H1 Table 2]`）→ 边际成本优势成立；MBPP+ ConvRSI = 695/431 = 1.613 vs RecursiveMAS = 1249/776 = 1.609（复算）→ **不成立**。
- 可测条件 2：同时报"总 benchmark 墙钟"与"单题 p50/p95 延迟"。已抓到的只有总墙钟；若 p95 不降，则"并行"只是吞吐优化，不是交互式延迟优化（**未核**）。

**判据 C：成本收益是真的吗？——把三本账分开报。**
- 生成 token 数：要求 `(Tokens_base − Tokens_conv)/Tokens_base` 可复算（MATH-500 17.27% 成立；MBPP+ 4.42% 成立但小）。
- 推理 GPU 时间/能耗：要求给出设备、精度、batch；论文只给 RTX 4090D 墙钟（可复现但不含能耗）→ 部分可测。
- 训练 GPU 小时 × 重训频率：论文**未核**。若换 benchmark 需重跑 Outer（∝ r），则总成本未必下降：这是"串行成本转移给训练"的判别式——**判训练摊销是否 < 推理节省**。

**判据 D：精度收益是方法还是数据？**
- 可数条件：训练/测试去重后的重叠行数。README 自报 6 条归一化后与 MATH-500 完全相同 `[R1]`；要求去重叠后重跑，并报四 seed 标准差（论文未核）。
- 可测条件：把 K（prefix tokens）、D、r 三个旋钮各自清零/减半做消融；若 `r=1` 时优势接近 0，则"并行深度"而非"卷积算子"是主因（现有读数：MATH-500 r=1 ConvRSI 71.6 vs RecursiveMAS 70.1，差 1.5pp；r=3 差 3.6pp，`[H1 Table 2]` 复算）。

**总判决**：ConvRSI 成立的条件 = 小模型 + 冻结 LLM + latent 免解码 + 同 r 同口径对比 + 轮内同步算子省下的解码成本大于 `R(C_local+C_graph)` 与 Outer 训练摊销。不满足时，它只是把串行的 token 解码成本换成串行的 r 轮隐状态迭代 + 一次性训练成本，**不是并行计算的普适替代**。

## 5. 遗留核对与口径混淆因子分解（用户 m01058「继续推进六个」，2026-11-19）

T1 原遗留是「77.8% vs 71.4% 口径冲突禁混比」（T8a 已定性）+「6/1904 训练测试重叠需去重」+「无四 seed 标准差」+「训练 GPU 小时未核」。本轮把「77.8% vs 71.4%」这组**口径混淆因子**做成可复算的分解表，作为判据 B 的补充：

### 5.1 同一 benchmark（MATH-500）两套读数的混淆因子分解

| 因子 | RecursiveMAS 自家读数 | ConvRSI 复跑读数 | 是否同口径 | 可复算的分解 |
|---|---|---|---|---|
| 精度（r=3） | 77.8% `[H2 Table 2]` | 71.4% `[H1 Table 2]` | ❌ 不同 | 差 6.4pp；论文未给两套读数的 bridge 实验（同代码同 seed 对跑）→ **禁止相减** |
| 时间（r=3） | 1360s `[H2 Table 2]` | 2658s `[H1 Table 2]` | ❌ 不同 | 差 1.95×；若同代码同硬件，1.95× 只能来自实现/批大小/最大 token 设置差异，论文未列 → 未核 |
| 生成 token（r=3） | 519 `[H2 Table 2]` | 556 `[H1 Table 2]` | ❌ 不同 | 差 7.1%；接近但未对齐（可能是 max-token 截断口径） |
| 硬件 | RecursiveMAS 未逐条报（H2 只给总数） | RTX 4090D，四 seed | ❌ | 硬件差无法排除 |
| 随机 seed | 自家 5 runs（H2） | 4 seeds（H1） | ❌ | seed 数不同，方差口径不同 |
| 测试集 | MATH-500 全量 | MATH-500 全量 500 题 | ✅ 同 | 唯一对齐的因子 |

**分解结论**：两套读数在「测试集」一项对齐，其余（代码版本、实现、硬件、seed 数、max token）全不对齐。所以 77.8% 与 71.4% 的差（6.4pp）**不能归因为「RecursiveMAS 更强」或「ConvRSI 更弱」**——它是一个未分解的混合差。要分解必须跑 bridge 实验（同一份代码、同一硬件、同一 seed 数各跑两套），论文没给。**这条遗留不是「未核」而是「不可分解」：缺少 bridge 实验，6.4pp 不能归因单一因子。**

口径精确化（七挖法审计 #7，2026-11-20）：原文「任何相减都是口径错误」过绝。正确表述是——**6.4pp 可相减为跨系统描述差**（两个不同系统在本任务上的表观差距），但**不可作同口径 A/B 比较、不可归因为「RecursiveMAS 更强 / ConvRSI 更弱」**。差别在于：描述差是"两个数不一样"的事实陈述，归因是"因为某因子所以更强"的因果陈述；前者允许相减，后者需要 bridge 实验。

### 5.2 对判据 B 的补强

原判据 B 的可测条件 1（g_method = T(3)/T(1)）已经在 3.1 给出：
- MATH-500：ConvRSI 1.256 vs RecursiveMAS 1.886 → 边际成本优势成立
- MBPP+：ConvRSI 1.613 vs RecursiveMAS 1.609 → 不成立

本轮补一个**同 benchmark 内部**的比值（不跨论文，只用 ConvRSI 自己的 r=1/r=3 两组数），这个比值**不受口径混淆影响**：

| benchmark | T(1) | T(3) | T(3)/T(1) | 含义 |
|---|---|---|---|---|
| MATH-500 | 1162s | 1459s | 1.256 | ConvRSI 自己：多 2 轮只涨 26% 时间 |
| MBPP+ | 431s | 695s | 1.613 | ConvRSI 自己：多 2 轮涨 61% 时间 |

同 benchmark 内比值不受跨论文口径影响，所以「ConvRSI 在 MATH-500 上轮内并行收益大、在 MBPP+ 上几乎消失」这个结论**是稳的**——它只用 ConvRSI 自己的数，不依赖 RecursiveMAS 的任何读数。
