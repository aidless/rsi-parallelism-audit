## 2. 「开放」的四条判据

判据定义：novelty＝档案里是否出现新机制而非仅调参；archive growth＝档案是否持续变宽且旧节点不被丢弃；transfer＝是否做了跨 benchmark / 跨域的留出测试；no-terminal＝是否没有固定终止预算。

| 判据 | DGM | Hyperagents |
|---|---|---|
| novelty | **是**。摘要逐字列新行为："better code editing tools, long-context window management, peer-review mechanisms"；v3 §4.4 明确说是 "novel and potentially useful self-modifications beyond immediate performance gains" | **是**。v2 摘要列新 meta 机制 "persistent memory, performance tracking"；v1 正文 §E.3 还有 "Automated Bias Detection and Correction"、"Compute-Aware Strategic Planning" |
| archive growth | **是**。v3 §3："continuously accumulates all generated variants over time"；入档条件是 `c.is_valid()`（"Keep children capable of code editing"），**没有分数闸**；80 iterations 持续产生新节点 | **是**。v1 §7："open-endedly evolves an archive of self-improving hyperagents"；v2 摘要："accumulate across runs" |
| transfer | **是，但限编码域内**。v3 §4.4："The best agent evolved on SWE-bench achieves 28.9% on Polyglot, compared to the initial agent's baseline of 14.2%. Conversely, the best agent evolved on Polyglot achieves 24.5% on SWE-bench, outperforming the original baseline of 20.0%." 且 "Since each agent was optimized without ever accessing the alternate benchmark, these evaluations represent truly held-out tests." 另有跨模型（o3-mini 23.0%→33.0%；Claude 3.7 Sonnet 19.0%→59.5%）与 Python→其他语言迁移。**无跨编码域（如迁到论文评审/数学）的任务层迁移实验** | **是，但限 meta-level**。v2 摘要："these meta-level improvements transfer across domains and accumulate across runs"；v1 §5 区分两种迁移："Improvements to the task agent transfer to held-out test tasks within each domain"、"Meta-level improvements transfer across domains, enabling hyperagents to significantly improve their ability to generate better task agents in previously unseen domains"。**任务分数跨域直迁无证据** |
| no-terminal | **否**。v3 §4.1："We run the DGM for 80 iterations (generating one new agent per iteration)"；算法伪码为 `for t ← 1 to T do` | **否**。v1 实验：Polyglot "same number of 80 iterations"；部分实验 "run for 100 iterations"；改进率度量 "All experiments in this section run for 50 iterations"；v1 §7 自承 "it operates with a fixed task distribution" |

**判据汇总判断**：两条「是」（novelty、archive growth）说明它们开放的是**搜索空间**；transfer 一条只在限定范围内成立；no-terminal 明确为否。因此 DGM 论文标题里的 "Open-Ended" 指的是不预设单一最优解、保留所有中间台阶的探索策略（v1 引入的 open-endedness 定义："continually invent new, interesting, and increasingly complex artifacts, extending its own frontier of discovery without a fixed objective or predefined end"），**不是无终止条件的环境演化**。

**一个不能混同的细节**：盘上笔记 `notes/2026-11-19-rsi-deep-projects-more.md:101-102` 记录的 "per-benchmark 非回归过滤" 是 **lemoz/darwin-godel-machine 第三方复现**的选择闸（`archive/parent_selector.py:26-32,207-243`）；原文 DGM 是 "paper-faithful — no score gate" 的复现对照。引用时只能说「复现实现加了非回归闸」，不能当作原论文机制。

## 3. meta-level 可编辑性：什么变了，什么没变

**核心判断**：Hyperagents 把搜索空间从「agent 代码」扩成「agent 代码 + 编辑器 + 编辑器的编辑规则」，但**判分权没有一起下放**：任务分布、父选择、评估协议都留在人写的外环里。二阶风险（自我指涉的验证器谁来判分）由此被「冻结外环」压住，而不是被解决。

v2 摘要逐字（已验 abs 页）：

> "We introduce \textbf{hyperagents}, self-referential agents that integrate a task agent (which solves the target task) and a meta agent (which modifies itself and the task agent) into a single editable program. Crucially, the meta-level modification procedure is itself editable, enabling metacognitive self-modification, improving not only the task-solving behavior, but also the mechanism that generates future improvements."

> "We instantiate this framework by extending DGM to create DGM-Hyperagents (DGM-H), eliminating the assumption of domain-specific alignment between task performance and self-modification skill to potentially support self-accelerating progress on any computable task."

v1 正文 §7 Limitations 逐字（2026-03-19 版 HTML 全文，已打开）：

> "First, it operates with a fixed task distribution. One direction is to co-evolve the task distribution by generating new tasks and curricula that adapt to the agent's capabilities."

> "Second, components of the open-ended exploration loop (e.g., parent selection, evaluation protocols) remain fixed. Although hyperagents can modify their self-improvement mechanisms, they cannot alter the outer process that determines which agents are selected or how they are evaluated. Keeping these components fixed improves experimental stability and safety, but limits full self-modifiability."

v1 正文 §6 Safety 逐字：

> "Moreover, evaluation is performed using predefined tasks and metrics, and human oversight is maintained throughout all experiments."

DGM v3 §5 Safety Discussion 逐字：

> "Modifications optimized solely for benchmark performance might inadvertently introduce vulnerabilities or behaviors misaligned with human intentions, even if they improve the target metric"

第三方对这条线的定位（MetaShare 摘要逐字）：

> "Open-ended self-improving agents can share experience across lineages, as in GEA, or edit their own improvement mechanisms, as in DGM-Hyperagents, yet failed improvement attempts are rarely retained as reusable cross-branch knowledge, and search can collapse onto redundant strategies."

| 维度 | DGM | DGM-Hyperagents | 变化？ |
|---|---|---|---|
| 可编辑对象 | task agent 代码；自改同时提升「改代码的能力」，但依赖 coding 域对齐（v2 摘要："Because both evaluation and self-modification are coding tasks"） | task agent + meta agent + meta 修改过程（单一可编辑程序） | **变了**：一阶→二阶，「域对齐」假设被显式移除 |
| 迁移对象 | 演化出的 agent 本身（跨模型/基准/语言） | 主要是「如何改进」的机制（persistent memory、performance tracking）跨领域、跨 run 积累 | **变了**：迁移从 artifact 转到改进器 |
| 判分器 | 固定 coding benchmark + `is_valid()` 功能校验 + sandbox / human oversight | 固定任务分布 + 固定 evaluation protocol + predefined tasks/metrics + human oversight | **没变** |
| 终止 | 80 iterations / 固定 T | 80 / 100 / 50 iterations / 固定 T | **没变** |
| 环境 | 固定 benchmark | 固定任务分布；co-evolve task distribution 被作者写进 future work | **没变** |

**二阶风险的具体形状（分析，非作者原话）**：当 meta-level（如 "Better Evaluation Analysis"、"Automated Bias Detection and Correction"，v1 §E.3 标题）本身可编辑时，档案里「评分」这一列的可信度依赖两层：内层自我指涉的验证逻辑可由 agent 改写，外层仍是冻结的 benchmark 与人写指标。两层错位时，agent 可以优化「看起来在正确评估」而不改变真实任务表现——DGM §5 那句 "even if they improve the target metric" 正是这个 Goodhart 形状。论文选择把父选择与评估协议钉死，使内层验证器无法篡改最终判分；代价是判分器永远不是被演化对象，「开放」停在搜索侧。MetaShare 又加了一个 "task-blind auditor" 来注入缺席的机制类别——这是把「谁判什么算新」外置成第三个 judge，judge 数量增加而非消失。

## 4. 缺口：没有「环境开放 + 可迁移判分」同时成立的基准

判定门槛：① 环境开放＝任务分布或判分规则随 agent 一起变化，或环境持续产出 agent 未见过的新任务；② 可迁移判分＝同一分数口径可跨域比较，且有跨 benchmark / 跨域的留出迁移实验。两者必须同时成立。

| 查过的 benchmark / 域 | 查证来源（均已打开） | 环境开放？ | 可迁移判分？ | 缺哪一维 |
|---|---|---|---|---|
| SWE-bench / SWE-bench Verified（-mini 子集） | [arXiv:2310.06770](https://arxiv.org/abs/2310.06770) 200 + DGM v3 §4.2 | 否：静态 GitHub issue 集，Verified 是人工筛可解子集 | 只在编码域内（DGM 跨到 Polyglot） | 环境开放；跨域判分 |
| Polyglot（Aider leaderboard 设定） | DGM v3 §4.2 与参考文献 "Paul Gauthier (2024)"（经 DGM 正文引用，未直接引原链接） | 否：固定多语言题集，实验用 50 题子集 | 与 SWE-bench 互迁，仍属 coding | 环境开放；跨域判分 |
| Paper Review | Hyperagents v1 §C.2 / §5；原文："We do not aim to change the peer review system, but rather, we study whether hyperagents can automatically learn decision procedures that align with observed human judgments." | 否：任务固定、判分对齐人类评审 | 同域 held-out | 环境开放；跨域判分 |
| Robotics Reward Design（Genesis） | Hyperagents v1 §C.3 / §5 | 否：固定仿真任务，zero-shot 生成新 reward function | 同域 held-out | 环境开放；跨域判分 |
| Olympiad-level Math Grading | Hyperagents v1 §C.4；原文："This domain is reserved as a held-out meta-evaluation to test whether DGM-H's improvements to its self-improvement process transfer across domains and continue to compound over time." | 否：固定题库，且被专门留作 held-out | 只验 meta 改进迁移，不验任务分跨域 | 环境开放；任务分可迁移 |
| OpenProblems / NatureBench / MLE-Bench Lite | [arXiv:2610.20431](https://arxiv.org/abs/2610.20431) 摘要（SwarmRSI） | 否：固定科研任务集 | 有 "held-out tasks" 提升，但各集独立评分 | 环境开放；跨域判分 |
| Knowledge incorporation / few-shot generalization | [arXiv:2506.10943](https://arxiv.org/abs/2506.10943) 摘要（SEAL） | 否：固定自编辑训练/测试输入 | 摘要未报跨域迁移 | 两者皆缺 |
| cap set / admissible set / bin packing（FunSearch 系统 evaluator） | [Nature s41586-023-06924-6](https://www.nature.com/articles/s41586-023-06924-6) 摘要 | 否：每个问题一个人工写死的 evaluator | 未报跨域判分 | 两者皆缺 |
| 数据中心调度 / 硬件电路 / 数学开放问题（AlphaEvolve） | [arXiv:2506.13131](https://arxiv.org/abs/2506.13131) 摘要 | 否："receiving feedback from one or more evaluators"，evaluator 由人定义 | 未报跨域统一分数 | 两者皆缺 |
| coding / science / math（ADAS, Meta Agent Search） | [arXiv:2408.08435](https://arxiv.org/abs/2408.08435) 摘要 | 否：各域固定任务 | 摘要明确报 agent 自身 "maintain superior performance even when transferred across domains and models"；但各域各算分 | 环境开放；统一可迁移判分 |
| paper review / coding / math grading / robotics reward / financial audit-risk（MetaShare 五域） | [arXiv:2610.21887](https://arxiv.org/abs/2610.21887) 摘要 | 否：五域任务集各自固定（"task-blind auditor" 只注入机制类别，不生成任务） | 跨域比较的是「达到最佳 agent 所需迭代数」，不是统一任务分 | 环境开放；跨域判分 |

**缺口结论（可引用）**：最硬的证据来自 Hyperagents 作者自己——"co-evolve the task distribution by generating new tasks and curricula" 仍是 "One direction"，而 "evaluation protocols remain fixed"（v1 §7）。DGM 的 transfer 是 benchmark→benchmark，但两端都是 coding；Hyperagents 的 transfer 是 meta-mechanism→domain，任务分只在同域 held-out 上验；ADAS 虽明确报了跨域迁移，仍是在人写死的任务分布上分别算分；MetaShare 跨五域却以相对迭代数而非统一可迁移分数作比较。查过的这 11 组基准中，没有一组同时满足「环境开放」与「可迁移判分」——open-endedness 要求 no fixed objective，benchmark 要求 fixed metric 才可比，这个结构张力本身就是缺口。

## 5. no-terminal 的量化：终止来源三分法（用户 m01058「继续推进六个」，2026-11-19）

原判据 4（no-terminal）只给了布尔「否」。本轮把它升级为**终止来源的三分法**——因为「有没有终点」这个问题的可测形式不是「跑了多久」，而是「谁决定停」。

### 5.1 三档定义（可判定）

| 档 | 终止来源 | 判据（可数/可测） | 是否算环境开放 |
|---|---|---|---|
| **S0 作者写死** | 作者在函数签名/实验设置里给定有限 T | 源码/正文出现 `for t ← 1 to T`、`run for N iterations`，且 N 是常数 | ❌ 否 |
| **S1 收敛判据** | 改进率/适应度增量低于阈值即停 | 出现 `if improvement < ε: stop`；ε 由作者设 | ❌ 否（终点仍由设计者定义） |
| **S2 环境给终止** | 任务流枯竭/环境发出终态信号才停 | 终止条件来自环境返回的状态，不是作者常数 | ✅ 是 |

### 5.2 DGM / Hyperagents 的实测归类

| 系统 | 正文/摘要里的 T | 出处 | 归类 | 可测含义 |
|---|---|---|---|---|
| DGM | 80 iterations（"generating one new agent per iteration"）；算法 `for t ← 1 to T do` | v3 §4.1、§4.4 | **S0** | 档案累积 80 节点即停；T 是作者常数，与环境无关 |
| Hyperagents（Polyglot） | "same number of 80 iterations" | v1 实验 | **S0** | 同上 |
| Hyperagents（部分实验） | "run for 100 iterations" | v1 实验 | **S0** | 换实验仍写死另一个常数 |
| Hyperagents（改进率度量） | "All experiments in this section run for 50 iterations" | v1 §实验 | **S0** | 连"改进率"本身的度量窗口都是作者写死，不是收敛触发 |

**量化结论（可引用）**：DGM 与 Hyperagents 的全部已核实验，终止来源 100% 落在 S0（作者写死有限 T ∈ {50, 80, 100}）；**S1（收敛触发）与 S2（环境终止）均为 0 例**。Hyperagents v1 §7 自承 "fixed task distribution" 与这个 S0 归类互为印证——**任务分布冻结 + 作者写死 T = 选择压力来自设计者，不是环境**。这正是 PNAS eAI 区分的 breeder 场景，而非 ecosystem 场景。

### 5.3 与终局判断的接口（不硬套数）

注意：S0 的「80 节点档案」
- **不是** T10 里「一次抽 N=80 个候选」的底物——DGM 的 80 个变体是 80 代累积、每代基于当时最优父代变异，跨代相关结构与 T10 的同代局部扰动池不同。
- 因此**不能**把 T10 的 ρ=0.945 → N_eff≈1.6 直接套到「80 节点档案」上。那样会犯 T10 §局限里已经记过的量纲错（把不同底物的相关结构当同一个量）。

正确的接口写法是：S0 归类只说明「终点由谁定」，不说明「档案里 80 个变体的独立度是多少」——后者需要**在 DGM 档案上量跨代 Δ 向量的 ρ̄**（T5 五个可测量里的 N_eff/N），这是一个待做的新实验，属 T12 之后的方向，不是本轮未竟事项。
