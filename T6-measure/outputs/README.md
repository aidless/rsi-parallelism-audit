## 1. arXiv 词频量表（2025Q4–2026Q3）

复现：
```bash
cd analyses/tracks/rsi-after/T6-measure
python3 arxiv_rsi_lexicon.py --self-test        # 8 个真阴/真阳样本，exit=0 才有效
python3 arxiv_rsi_lexicon.py --quarters 2025Q4 2026Q1 2026Q2 2026Q3 --out outputs --sample 100 --sleep 3
```
arXiv API：`(cat:cs.AI OR cat:cs.CL) AND submittedDate:[lo TO hi]`，三类词用 `abs:"..."` 宽召回；本地用严格正则复核（ARCH 必须命中强信号之一，避免把 arXiv 的 "archive" 误计）。

| 季度 | 总论文 | ARCH API | ARCH/万 | REC API | REC/万 | VER API | VER/万 | ARCH/REC |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 2025Q4 | 15038 | 274 | 182.21 | 365 | 242.72 | 1239 | 823.91 | 0.75 |
| 2026Q1 | 17135 | 393 | 229.36 | 396 | 231.11 | 1847 | 1077.91 | 0.99 |
| 2026Q2 | 22246 | 599 | 269.26 | 475 | 213.52 | 3042 | 1367.44 | 1.26 |
| 2026Q3 | 19989 | 646 | 323.18 | 508 | 254.14 | 3580 | 1790.99 | 1.27 |

本地复核（每季每类抽 100）：ARCH 命中 96/90/92/79，REC 86/97/94/97，VER 50/69/84/84。证据明细见 `evidence.jsonl`（1018 条，含 matched 词与摘要片段）。命中词分布：ARCH 几乎全由 `open-ended`（352/357）驱动；VER 由 `audit`（187/287）和 `verifier`（121/287）驱动，`audit` 是泛词。剔除 `audit`/`evaluator` 后重算 VER API 命中为 1012/1422/2188/2515，即每万篇 672.96/829.77/983.46/1258.19（+87%），增长仍显著——不是泛词单独造成的。

**读数**：ARCH/万 从 182.21 涨到 323.18（+77%），REC/万 在 214–254 之间基本平；ARCH/REC 在 2026Q1 跨过 1。VER/万 从 823.91 涨到 1790.99（+117%），增速高于 ARCH。方向性上支持"重心从递归转到演化/验证"，但这是**语料词频（B 级）**：关键词定义、社区术语漂移、arXiv 词干化都会改变读数，且命中不等于论文真的做了这件事。不能当因果证据。

**显著性口径（七挖法审计 #3，2026-11-20）**：+77%/+117% 是 4 个季度点的比例点，**从未做趋势检验/CI/多重比较校正**（3 类词×4 季共 6 检验，Bonferroni α=0.0083）。已复算：Kendall tau = ARCH 1.0 / VER 1.0 / REC 0.0（前两者严格单调、REC 无方向），命中率 n=100 的 Wilson 95% CI 末季 ARCH [0.898,0.979]。因为这些读数只能标**描述性趋势**，不能写成"显著上升"——要提升到显著需原始论文级计数（CSV 只有 4 个聚合比例），属下一轮投入。

## 2. 验证器吞吐-速率协议（rsi-agent 挂载，8 代 smoke）

复现（工作区根目录）：
```bash
python3 analyses/tracks/rsi-after/T6-measure/verifier_throughput_rsi.py \
  --rsi-root rsi-agent --generations 8 --seeds 7 17 27 \
  --out analyses/tracks/rsi-after/T6-measure/outputs
# 负对照：加 --random-select（候选判分成本相同，但随机挑候选、不按分选优）
```
设计：不改 rsi-agent 源码。`MeteredTask` 包装公开集 `evaluate` 统一计数；`BatchInnerAgent` 沿用原 InnerAgent 的锚点+步长衰减高斯扰动分布，每代抽 N 个候选、按公开分选最好；密封集仍由 `runner.py:143-145` 在过公开闸后才触碰，`sealed_evaluations` 独立记录。3 条件 N=1/4/16 × 3 inner_seeds × 8 代。速率 = Δbest_public_mean / 验证调用数。

主实验（3 seeds 均值，8 代）：

| N | 平均验证调用 | Δ best | rate/1k 验证 | 平均 promoted |
|---:|---:|---:|---:|---:|
| 1 | 29.7 | +0.4011 | **+13.376** | 3.67 |
| 4 | 56.3 | +0.4855 | +8.619 | 6.33 |
| 16 | 152.7 | +0.4933 | +3.231 | 6.67 |

负对照（随机选候选）：

| N | 平均验证调用 | Δ best | rate/1k 验证 | 平均 promoted |
|---:|---:|---:|---:|---:|
| 1 | 29.7 | +0.4011 | +13.376 | 3.67 |
| 4 | 51.7 | +0.3220 | +6.233 | 1.67 |
| 16 | 147.3 | +0.3034 | +2.058 | 1.33 |

**读数**：绝对改进在 N=4 已近饱和（0.4855 → 0.4933，+1.6%），但验证调用翻近 3 倍，所以单位验证速率单调下降 4 倍；负对照让 N=4/16 的速率再降 28%/36%，说明增量来自*"多候选里挑最好"这个选择动作*，不是"多付判分费"本身。

**负对照口径精确化（七挖法审计 #6，2026-11-20）**：候选判分次数 = width×generation，两臂按构造严格相同（protocol Ns/seeds/generations 全同），与选择策略无关；但每次 promoted 多触发一次 public 确认评估 + 一次密封确认，随机选择过闸率低→promoted 少（N=4 主 6.33 vs 随机 1.67）→总 `verifier_calls` 与密封评估随机侧更少（N=4 56.3 vs 51.7、N=16 152.7 vs 147.3）。所以「仍付 N 次判分」应精确为「**候选判分成本相同，总评估成本随机侧更少**」；负对照本身成立（主 Δ−随机 Δ = 0.1635(N=4)/0.1899(N=16)）。这是协议可行性验证（**B 级，toy 任务**）：rsi-agent 是合成 BinPack、公开分就是廉价真值代理，没有真实 LLM 判分误差。它证明曲线可测，**不**证明真实系统里也存在同样的饱和点。真实 scaling 曲线仍缺（见 T5）。

---

边界：以上所有数字都能从落盘 JSON 与 arXiv 响应重算。结论只到"方向性支持 + 曲线可测"，不外推到真实科研系统的改进速率。
