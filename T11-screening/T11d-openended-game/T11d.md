## 2. 六门槛打勾（Dreaming in Code）

| 门槛 | 判定 | 逐字证据 / 理由 |
|---|---|---|
| A1 no-terminal | **红（打折）** | 训练目标是固定目标环境 Craftax（"To scaffold progress toward the target environment"、"20% Target Environment"），held-out 是 "1024 unseen procedurally generated worlds"（项目页 Key Results）。生成了无限多 intermediate levels，但终点固定，不是无终止环境演化 |
| A2 分布漂移 | **绿** | "Unlike standard UED methods that only randomly rearrange map tiles, DiCode programmatically specifies the whole environment logic. It algorithmically specifies the world topology, redefines interaction rules and progression logic, and defines specific objectives for each level."（项目页 Dreaming in Code Loop / Generation Cycle）——生成的是全新环境逻辑与目标，不是同分布采样 |
| A3 压力来自交互 | **部分绿** | 选择压力由 learnability score（Zone of Proximal Development）驱动、把 agent 当前能力当输入：`"Using a learnability score, the selector identifies "parent" levels that are currently in the agent's Zone of Proximal Development."`。但 selector 是人写死的度量，不是生态系统自发选择 → 介于 breeder/ecosystem 之间 |
| B1 held-out 迁移 | **红/部分** | 只有同域 held-out：`"Mean episode return on the held-out test set (1024 unseen procedurally generated worlds) ... 48.55 vs 41.59 ... ~17%"`。无跨任务域/跨环境的排名相关（Spearman ρ）实验 |
| B2 抗 Goodhart | **未核/红** | 唯一的生成物校验是 `"Before training, every generated level undergoes a compilation check to filter out invalid code."`（项目页 Training）。无独立 adjudicator、无未入环重打分、无 reward-hacking 防护证据 |
| B3 判分器外环冻结 | **绿** | 判分是游戏内 reward（Craftax 内置），不随生成器/agent 共演化；生成的是训练环境，判分口径不变 |

**综判**：六项不全绿；核心 4 项中 A2 绿、B1/B2 红、A1 打折。**不是证伪入口**。

## 3. 一个值得记下的机制（对本项目判断有用）

DiCode 最接近「环境开放」的机制是**用基础模型合成可执行环境代码**，把 curriculum 从「重排地图瓦片」升级到「重写世界规则与目标」。这正好是 T2 缺口里「环境侧开放」的正样本形状——但它服务的仍是**固定目标环境上的 RL 训练**，判分外部性只来自游戏内置 reward，没有跨环境可迁移的统一分数。也就是说它把 A2/A3 做实了，B 侧仍是同域验证。这个组合（A 强 + B 弱）与 T3 的 SwarmWorld 同型。

## 3.5 补充：Open-world evaluation / CRUX 这条线（理论价值高，但不构成证伪入口）

[CRUX / Open-world evaluations for measuring frontier AI capabilities](https://www.normaltech.ai/p/open-world-evaluations-for-measuring)（Kapoor, Narayanan et al., 2026-04-16，17 人合作；正文 8000 词，另有 PDF 版 cruxevals.com/open-world-evaluations.pdf）——**这是评测方法论文章，不是可执行基准**，但它的核心论证直接解释了本项目 T2 缺口的成因，值得记一句：

> 原文逐字："To turn a task into a benchmark, it needs to be precisely specified and automatically verifiable. The catch is that whatever is precise enough to benchmark is also precise enough to optimize for." 以及 "Benchmarks avoid real-world messiness... open-world evaluations consist of small samples, often require human intervention, and are evaluated in an open-ended way, such as by analyzing agent logs."

它把评测分成五级梯度（Q&A → open-ended chat → outcome-only agent → agent+log analysis → open-world），第五级 open-world 定义为 "long-horizon tasks in real-world environments, where success can't be neatly specified or automatically graded"。它自承局限：sample size 常为 1、"Hard to compare agents"、"Non-stationary environments" 使跨时间比较失效、成功标准模糊。

**六门槛速判**：A1 绿（真实世界长任务、无终点）、A2 绿（真实环境非静态集）、A3 绿（真实交互、人在环），但 **B1 红（自承 "not useful for comparing the accuracy of different models or agents"）、B2 未核/红（定性 log 分析+人工干预，无自动抗 Goodhart 机制）、B3 红（判分是开放式的、非冻结口径）**。→ A 满 B 空，与 SwarmWorld 同型，不是证伪入口。

**对本项目的理论价值**：它从评测方法论侧面**独立佐证了终局判断**——「环境开放」与「可迁移判分」的结构张力不是没人想到，而是评测领域公认的两难：判分越精确可自动化（B 强）就越可被优化/越脱离真实环境（A 弱），反之亦然。CRUX 选择牺牲 B 换 A，benchmark 选择牺牲 A 换 B，两者互补但没有合流。这正是路 2 要缝合的点。它 survey 的 10 个 open-world eval（Claude 玩宝可梦、Project Vend、Carlini C 编译器、Karpathy nanochat autoresearch 等）都是单次 long-horizon 实验，无 one 满足 B1。

## 4. 本组结论

- 开放世界/游戏环境这条线**未筛到证伪入口**：DiCode 的 A2 绿但 B1/B2 红；CRUX 一条线 A 满 B 空；NetHack 是老 RL 环境不构成 self-improvement 基准。
- DiCode 是这条线里「环境生成」机制最硬的正样本（可执行环境代码 + 可学习前沿选择），如果路 2 要造基准，它的「生成器」部分可以直接借；缺的正是「跨环境 held-out 判分 + 独立 adjudicator」。
- CRUX 从方法论侧面独立佐证「环境开放 vs 可迁移判分」的结构张力（判分精确性 ↔ 环境真实性两难），是终局判断的外部交叉证据。
- 遗留未核：Craftax abs 页、DiCode 全文（HTML v2）中是否补了跨 benchmark 的 held-out（只读了项目页与摘要，未逐段搜 "transfer"/"cross-domain"）；CRUX survey 的 10 个 eval 未逐条套门槛（但它们自承 sample size=1，B1 必红，无逐个核的价值）。
