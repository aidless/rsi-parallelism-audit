## 3. 本组结论

- **无证伪入口**：8/8 候选六项未全绿；核心四项（A1,A2,B1,B2）全绿者 0。
- **A1 分布**：多为「有限流式」（🟡），无一做到无固定测试集终点；CL-Bench 自承序列 "on the order of tens ... short"。
- **A2 分布**：全部为预定义 task 序列 / 预定义 concept drift / 固定数据集排序（🟡或🔴），无一由环境交互自发吐出系统没见过的新任务类型。
- **A3 压力**：8/8 为🔴或框架写死 verifier——选择压力来自人写的 reward / 源基准 ground truth，不是 ecosystem 交互。
- **B1 迁移**：仅 EvoAgentBench 达绿（train/test split + 跨域跨 backbone held-out，construction/evaluation backbone disjoint），但其 A1/A2 红；其余为同基准内 instance/task 迁移或⚪，且**全部未见 Spearman ρ 一类排名相关数字**。
- **B2 抗 Goodhart**：无一有独立 adjudicator 在优化期未入环重打分 / verifier hardening；最强的 CL-Bench 靠专家验证 + gain 对照、EvoAgentBench 靠防测试信息泄漏，均为弱证据（🟡）。
- **B3 冻结**：多数为🟢（固定 ground truth / 冻结源基准 verifier / 冻结外部 GPT-5.4 基线），这是本组唯一成片达标的维度——但「判分器冻结」单独不构成证伪入口。
- **对主项目的判读**：持续学习主线提供的是「开放的经验机制 + 冻结的任务与判分」，与 T2 的 self-improvement 主线同构；要凑齐「环境开放 + 可迁移判分」，仍需 A2（ecosystem 自发新任务）与 B1（跨环境 held-out 排名相关）+ B2（未入环重打分）同时成立的基准，本组没有。建议后续不再在这条主线加候选。
- **遗留未核**：CL-Bench 官网 continual-learning-bench.com；所有候选的 Spearman ρ/排名相关数字；LifeMem、StreamBench 的判分器冻结声明；各候选 B2 独立 adjudicator 细节（全文未见即标未核，未编造）。
